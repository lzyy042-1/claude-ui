# claude-ui

给 **Claude Code** 套的一个图形界面。三栏 + 一块无限画布。

它不是"更好看的终端"。它想试一件事:

> **和 AI 相处,为什么只能靠打字?**

---

## 它是什么

```
┌───────────────┬────────────────────┬───────────────┐
│ 过程流        │ 会话  或  画布      │ 状态          │
│ 人话事件      │                    │ 硬件 /        │
│ + LOGS 原始流 │                    │ 上下文水位 /  │
│               │                    │ 成本          │
└───────────────┴────────────────────┴───────────────┘
```

- **左栏**把模型这一回合每次工具调用摊开 —— 终端里被折叠掉的过程,这儿全看得见
- **中栏**和它对话,也可以切成**一块无限画布**,拿手写笔直接画
- **底栏**除了打字,还有语音 / 画布 / 框选 / 拖拽四个入口

**它的"我"就是本机的 Claude Code** —— 同一个模型、同一份记忆库,只是换了个能看见过程的外壳。

## 它不是什么

- ❌ **不是独立的 AI 应用**。它给 Claude Code 套壳 —— **没装 CC 就是一坨死代码**
- ❌ **不是通用工具**。为一个人、一台机器写的。路径**能**配置,但不保证在别人机器上一跑就通
- ❌ **不是产品**。没有安装程序、没有自动更新、没有人在维护 issue

## 跑起来

```bash
# 1. 先装 Claude Code —— 它是命门
#    https://claude.ai/code

# 2. Python 依赖
pip install pywebview psutil pillow
pip install winrt-Windows.UI.Input.Inking winrt-Windows.Foundation \
            winrt-Windows.Foundation.Collections winrt-Windows.Storage.Streams winrt-runtime

# 3. 起
python app.py
```

**改配置**(CC 路径 / 端口 / 窗口大小 / 接哪个会话):

```bash
cp claude-ui.config.example.json claude-ui.config.json
# 然后改它。一个字段都不写也能跑 —— 全自动探测。
```

**打包成 exe:**

```bash
python -m PyInstaller claude-ui.spec --noconfirm
```

⚠️ `--noconfirm` 会把整个 `dist/claude-ui/` 删掉重建,**外置的 `index.html` 和 `canvas.json` 记得拷回去**(spec 里刻意没把 `index.html` 打进去 —— 这样改界面不用重新打包)。

## 几个自己拿的主意

**这部分比代码重要 —— 它决定了这东西长什么样。**

### 一、工作区是「状态」,不是「图层」

在画布上圈一块地方(矩形 / 圆 / 多边形 / 套索都行),点「选好了」= **进入**这个工作区。

从这一刻起,你画的一切都归它,**主画布上原来的东西一个字不动**。

收起它之后,你加的那些东西**不回原画**,作为「批注」一起收进这个工作区 —— 再打开才看得见。

> **这里没有「应用 / 合并」这个动作。**

理由:**原稿的意义就在于它是原稿** —— 涂改、犹豫、划掉的痕迹都还在。`Ctrl+S` 式的"把批注应用回去",等于拿干净的新版换掉它,过程就丢了。

### 二、原件只读,判断交给人

每一处需要判断的地方,都换成一个**人能做的动作**:

| 判断什么 | 交给谁 |
|---|---|
| 什么时候开口 | 人 |
| 哪块有用 | 人拖 |
| 哪几块是一组 | 人框 |
| 能不能改原件 | **不能** |

**为什么这样分**:"我想说什么"只存在于使用者脑中,不在任何数据里。哪两个东西是一起的,**不在像素里** —— 缸体、活塞、火花塞画在一张纸上,像素上就是三坨,自动分区只能按距离分,而空间邻近 ≠ 语义关联。

### 三、后端不解析语义

本地服务只做一件事:**把 Claude Code 子进程的 stdout 原样转发给前端**。

不解析、不改写、不"理解"。前端自己去认 `stream-json` 的每一帧。

**理由:一旦后端开始"理解"协议,它就变成第二个需要跟着协议变的东西。**

### 四、手写走系统自带,不调模型

画布上的手写,认字用的是 **Windows 自带的 `InkAnalyzer`**(识别器「Microsoft 中文(简体)手写识别器」)。

本地、离线、免费。认出来的字 + 坐标 + 图片位置,作为**结构**喂给模型 —— 它不用"看"像素,拿到的是 `circle at (812,1340)` 这种数据。

### 五、宁可看见失败,也别静默吞掉

正文里的依据角标(`[[eN]]`)跟工具调用次数对不上时,那几个字符**原样留在正文里**,不吞。

因为"对不上"本身就是个**该被看见的信号** —— 静默失败是最难查的那种 bug。

## 附加模块（`addons/`）

**画布不是本体的功能,它是一个附加模块。**

```
addons/canvas/
  canvas.js          界面（无限画布 / 涂鸦 / 工作区 / 蒙版）
  canvas.css
  canvas_server.py   后端（框选截图 / 画布存档 / 手写识别调用）
  handwriting.py     手写识别（走 Windows 自带的 InkAnalyzer）
```

**它在不在,决定你有没有画布** —— 本体启动时看一眼 `addons/canvas/`,不在就当没这回事
(底栏不出现「画布」,后端也不挂那几个接口)。

**接口只有两个方向、三个函数:**

| 方向 | 是什么 |
|---|---|
| 本体 → 画布 | `__initView()` / `__inkFit()` —— 切模式时通知重新量尺寸 |
| 画布 → 本体 | `CU.flow()` / `CU.raw()` —— 往左栏写一条;**没有就静默**,画布照样跑 |

**「AI 能看见画布」靠画布自己开口**:画布自己暴露 `/api/canvas`,工具条上有个
「**给AI看**」按钮 —— 点一下复制一句话,贴给模型,模型自己去拉。**本体不知道画布存在。**

> 曾经不是这样:本体会在你发消息时偷偷往尾巴挂一句指针。
> 2026-10-08 拆掉了 —— 那是把画布的能力和本体**捆在一起卖**。

## 已知的边界

- **强依赖本机的 Claude Code**。它改协议,这套就得跟着改
- **界面仍是单文件**(`index.html`,约 1100 行内联 CSS/JS),没框架、没构建。改一行刷新就见效
- **同时只能"进入"一个工作区**(可以同时**显示**多个,但新画的笔只归最后点开的那个)
- **工作区里还能再圈工作区** —— 现在没拦,会走进死胡同

## 想拿它干嘛

**它更像一个脚手架,不是一个成品。**

想改的话,入口都在这儿:

| 想改什么 | 去哪 |
|---|---|
| 路径 / 端口 / 窗口 / 会话 | `claude-ui.config.json`(见 `config.py`) |
| 界面(全部) | `index.html` —— 单文件,内联 CSS/JS |
| 后端接口 / 转发逻辑 | `server.py` |
| 窗口壳 / 权限桥 | `app.py` |
| 手写识别 | `handwriting.py` |
| **画布上的每一笔** | `canvas.json` —— **人类可读的 JSON** |

**画的每一笔都存成人能看懂的东西**,不是二进制。这是故意的。

改了哪儿别客气,直接提 PR。
